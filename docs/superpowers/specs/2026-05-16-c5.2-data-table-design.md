# C5.2 — Data Table View (design)

**Issue:** [#55](https://github.com/hanku4u/local-equs-client/issues/55)
**Milestone:** M5 — Polish & Admin
**Depends on:** C1.8 (QueryEngine)

## Goal

A virtualized table view of **raw** sensor values (no downsampling) with a separate query path from the chart grid. Lives behind a new "Table" tab in the main window. Visible row count stays bounded (~200) regardless of how large the underlying result set is.

## Architecture

### New modules

- **`src/local_equs_client/data_layer/raw_query_engine.py`** — `RawQueryEngine`
  - Separate query path from `QueryEngine`. No `time_bucket`, no aggregation.
  - Two public methods:
    - `count(plan: QueryPlan, *, cancelled: Callable[[], bool] | None = None) -> int`
    - `fetch_page(plan, *, offset: int, limit: int, order: Literal["asc", "desc"] = "asc", cancelled=None) -> pa.Table`
  - Both methods open a fresh `duckdb.connect(":memory:")`, run a single SQL, return the result, close the connection.
  - The view-side executor tracks the in-flight connection and calls `conn.interrupt()` to cancel superseded queries — mirrors `QueryEngine`'s pattern.

- **`src/local_equs_client/ui/data_table.py`** — `DataTableView` (`QWidget`)
  - Vertical layout: 1-line `QLabel` status bar on top, `QTableView` below.
  - Owns `_PagedRawValuesModel` (`QAbstractTableModel`). Page size = 200 rows.
  - Manages a single-worker `ThreadPoolExecutor` for `count` + `fetch_page` calls.

### Reused modules

- **`QueryPlanner.plan(selection, view_mode="standard")`** — produces the `per_tool_queries` list (file paths, raw column names per tool, time range). The raw query path ignores `target_resolution`. Reusing the planner gives us canonical→raw mapping, partial-data warnings, and missing-mapping reporting for free.

### Shared helpers

- Identifier / string-literal quoting (`_quote_string`, `_quote_ident`) currently live in `query_engine.py`. Move them to **`src/local_equs_client/data_layer/_sql.py`** so both engines share them rather than duplicating. Pure-function move; no behavior change.

### Modified modules

- **`src/local_equs_client/ui/main_window.py`** — replace `self._splitter.addWidget(self._chart_grid)` with a `QTabWidget` containing two tabs:
  - Tab 0 "Chart" → existing `ChartGrid`
  - Tab 1 "Table" → new `DataTableView`
  Both share the same `SelectionModel`, `LocalLibrary`, and `MetadataCache`. The `TimeRangeSelector` and `SensorPicker` stay where they are.

## UI Layout

```
MainWindow

└── QSplitter
```

### `DataTableView` widget

- **Tab labels:** `"Chart"` and `"Table"`. Default tab is `"Chart"`.
- **`QTableView` config:**
  - `setSortingEnabled(False)` — sort is wired manually so only the `ts` header reacts; other headers have no sort arrow and no-op on click.
  - `verticalHeader().setDefaultSectionSize(20)` for compact rows.
  - `horizontalHeader().setStretchLastSection(False)`; column widths sized to content on first load, then user-resizable.
  - Cell selection enabled (`SelectItems`). Ctrl+C copies the current selection as TSV via a small `keyPressEvent` shim. Full CSV export is C5.8 (#61) — out of scope here.
- **Status bar text rules:**
  - Plan has no `per_tool_queries` → `"Empty selection — pick a tool and sensor to view raw data."`
  - All tools have empty `raw_columns` after canonical→raw resolution → `"No mapped sensors for the selected tools."`
  - Loading first page → `"Loading…"`
  - Loaded, ≥1 row → `"Showing {first}–{last} of {total:,} rows"`
  - Engine error → red text, `"Query failed: {message}"`
  - Partial-data warnings from the planner → appended in parentheses: `"… (partial data: <warning>)"`
  - Cancellation is silent (the newer query's status replaces it).

## Data flow & lifecycle

### Initial show

1. User flips to the Table tab.
2. `DataTableView` reads the current `Selection` from `SelectionModel` and calls `QueryPlanner.plan(selection, view_mode="standard")`.
3. If `plan.per_tool_queries` is empty → show "Empty selection" status, leave the table cleared.
4. Otherwise, fire `RawQueryEngine.count(plan)` to size the scrollbar, then `fetch_page(plan, offset=0, limit=200, order="asc")` for the first page. Both run on the background executor.

### Scrolling

- `_PagedRawValuesModel.rowCount()` returns the cached `total_count` from `count()`. The model keeps the most recently fetched page (`offset` + Arrow table) in memory.
- `data(index)` for a row outside the loaded page returns `"…"` and schedules a `fetch_page(offset=floor(row/200)*200, limit=200, order=current_order)`.
- A new fetch issued while another is in-flight calls `conn.interrupt()` on the old one. The old fetch returns `QueryCancelled`; the model discards it without emitting `dataChanged`.
- When a page lands, the model emits `dataChanged` for the page's row range and the view repaints.

### Selection / time-range changes

- `SelectionModel.changed` and `TimeRangeSelector` changes both invalidate the table's cached `total_count` + page.
- If the Table tab is currently visible: immediately re-plan + re-fetch.
- If hidden: mark state dirty; switching to the tab triggers a fresh fetch.
- The two tab widgets stay mounted across switches — no widget teardown.

### Sort

- Click the `ts` header → toggle internal `order` between `"asc"` / `"desc"` → invalidate page cache → refetch from offset 0.
- Header arrow indicator follows the current order.

## Query path

### `fetch_page` SQL

UNION ALL of one SELECT per tool, ordered + paginated. The displayed column set is the **union** of every tool's `raw_columns`, sorted alphabetically. Each per-tool SELECT explicitly names that union: columns the tool's schema has are read directly; columns missing from that tool are written as `NULL AS "<col>"` so the per-tool SELECTs align for UNION ALL.

Example for `tool_a.raw_columns == ("chamber_pressure", "rf_power")` and `tool_b.raw_columns == ("chamber_pressure", "rf_power", "extra_sensor")` — displayed column set is `("chamber_pressure", "extra_sensor", "rf_power")`:

```sql
SELECT * FROM (
    SELECT 'etch_a1' AS tool_id, ts,
           "chamber_pressure", NULL AS "extra_sensor", "rf_power"
    FROM read_parquet(['/path/etch_a1_2026-01.parquet'], union_by_name = TRUE)
    WHERE ts >= TIMESTAMP '2026-01-01 00:00:00.000000'
      AND ts <  TIMESTAMP '2026-01-02 00:00:00.000000'
  UNION ALL
    SELECT 'etch_a2' AS tool_id, ts,
           "chamber_pressure", "extra_sensor", "rf_power"
    FROM read_parquet(['/path/etch_a2_2026-01.parquet'], union_by_name = TRUE)
    WHERE ts >= TIMESTAMP '2026-01-01 00:00:00.000000'
      AND ts <  TIMESTAMP '2026-01-02 00:00:00.000000'
)
ORDER BY ts ASC
LIMIT 200 OFFSET ?
```

- `union_by_name=TRUE` inside a per-tool `read_parquet([...])` is still needed because one tool may have multiple parquet files in `file_paths` with mildly differing schemas across time.
- UI column order in the `QTableView`: `tool_id`, `ts`, then the union-of-sensors sorted alphabetically.

### `count` SQL

Same UNION ALL of per-tool subqueries, wrapped in `SELECT COUNT(*) FROM (…)`. No ORDER BY needed.

### Public API

```python
class RawQueryEngine:
    def count(
        self,
        plan: QueryPlan,
        *,
        cancelled: Callable[[], bool] | None = None,
    ) -> int: ...

    def fetch_page(
        self,
        plan: QueryPlan,
        *,
        offset: int,
        limit: int,
        order: Literal["asc", "desc"] = "asc",
        cancelled: Callable[[], bool] | None = None,
    ) -> pa.Table: ...
```

## Error handling

| Condition | Display |
|---|---|
| `QueryPlan.per_tool_queries` is empty | "Empty selection" status; no query fired |
| All tools have empty `raw_columns` after canonical→raw resolution | "No mapped sensors for the selected tools." status (+ missing-mapping count from `plan.missing_mappings`) |
| `duckdb.Error` from `count` or `fetch_page` | Red status text with the message; table cleared |
| `QueryCancelled` (superseded fetch) | Silent — newer fetch's results replace it |
| `plan.partial_data_warnings` non-empty | Appended in parentheses to the normal "Showing …" status text |

## Tests

### `tests/unit/data_layer/test_raw_query_engine.py`

- `count` returns the right number of rows for a known small parquet fixture.
- `fetch_page` returns rows ordered by `ts` ASC for `order="asc"`, reversed for `"desc"`.
- `fetch_page(offset=N, limit=M)` returns rows `[N, N+M)` consistent with the same ordering.
- Multi-tool: result has a `tool_id` column with both tool ids present; sensors missing on one tool's parquet show as NULL.
- Empty plan → `count == 0`; `fetch_page` returns an empty Arrow table.
- `cancelled() -> True` mid-query raises `QueryCancelled` (same pattern as the existing chart-engine cancellation test).

### `tests/unit/ui/test_data_table.py`

- `_PagedRawValuesModel.rowCount()` returns the total count, not the page size.
- `data(index)` inside the loaded page returns the cell value; outside returns `"…"` and schedules a fetch (verified via injected fake engine).
- `dataChanged` fires for the page's row range when a fetch lands.
- Sort toggle: clicking the `ts` header switches `order` between asc/desc and invalidates the page cache.
- Selection change → invalidate + refetch when tab visible; mark dirty + don't fetch when hidden.
- Empty selection / missing-mappings / partial-data status text matches the rules above.

### `tests/unit/ui/test_main_window.py`

- Right side of the splitter is a `QTabWidget` with tab labels `["Chart", "Table"]` in that order.
- Switching to the Table tab triggers the first fetch on the `DataTableView`.

## Scope boundaries (deferred, not in C5.2)

- **CSV export of the table** — C5.8 (#61). C5.2 only ships Ctrl+C copy of the cell selection as TSV (small enough to be free).
- **Server-side sort by sensor columns** — Out of scope. Only `ts` is sortable; the issue's "sortable columns" wording is interpreted as "sortable by timestamp" for C5.2.
- **Tool dropdown / single-tool filter** — Multi-tool selections are merged via UNION ALL with a `tool_id` column. No tool-picker UI.
- **Telemetry events for table queries** — C5.13 (#66).
